Kent Bull, who works on the method at GLEIF, presents did:webs as a short step past did:web. The identifier is still a domain name, and the DID document still lives at a predictable URL. What the extra "s" adds is a second file, keri.cesr: a CESR stream of KERI and ACDC objects. That stream is how a verifier checks that the same controller still holds the identifier after keys rotate, which did:web cannot do. Hosting can move from one name to a backup, and the identifier stays the same because the key history proves it is the same controller.

The feature he treats as distinctive is the designated alias. The stream carries an explicit commitment that this identifier is authorized for this domain, and a verifier should reject a document that lacks it. The document also has to describe nested, weighted multisig rather than a single key. ConditionalProof2022 states the threshold and which keys may sign, so a verifier that is not a KERI specialist can tell a valid multisig proof from one lone signature.

An implementation and a resolver exist, and the method is meant to be tried. The specification still has to say how a stream declares its protocol version, how historical keys are read, and how KERI version 2 registry state works, including blinded registries and when they unblind.
